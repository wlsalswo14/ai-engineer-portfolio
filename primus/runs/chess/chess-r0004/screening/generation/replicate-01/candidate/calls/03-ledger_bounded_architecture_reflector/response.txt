# DESIGN_COMMITMENT

The sole champion trace is a harness failure: zero cases executed, zero engine failures observed, and no timing margin measured. Therefore no ledger relation is evidenced as champion-passing. I will treat every relation in the fixed ledger and the strict deadline rule as mandatory unverified obligations, while addressing the public relative regression through one connected whole-engine redesign.

The engine will remain a single standard-library-only `engine.py`, with no benchmark knowledge, external dependencies, opening logic, tablebases, or hidden-data access.

State ownership will be centralized in a complete position object containing board, side, castling rights, en-passant square, halfmove clock, fullmove number, king locations, deterministic hash, and evaluation accumulators. Every move will carry sufficient information for exact push/pop restoration, including captured pieces, en-passant removal, rook movement, promotion, castling-right changes, clocks, king squares, hash, and evaluation deltas. FEN parsing and UCI move application will reconstruct all six fields canonically. Search will never mutate protocol state permanently.

The data flow will be:

`UCI parser → canonical position builder → legal move generator → time-bounded iterative search → legal fallback/selected move → UCI serializer`

Protocol handling owns input/output only. State handling owns reconstruction and restoration. Move generation owns attacks, checks, castling, en-passant, promotion, and terminal classification. Search owns its stack and heuristics. Evaluation is read-only over the current state. The time manager is the sole authority allowed to stop search.

Core invariants are:

- Every emitted nonterminal move is independently legal and syntactically valid.
- Terminal positions emit exactly `bestmove 0000`.
- A move followed by its inverse restores the complete state exactly.
- FEN reconstruction and legal move walks produce equivalent canonical states.
- Search starts from a clean root context for every `position` command.
- Cache keys include all six state fields; no prior position, history, killer, or transposition residue can affect reconstructed-state behavior.
- Completed iterative-deepening results are the only results eligible for output.
- A legal fallback is established before deeper search begins.

The search will use deterministic iterative-deepening negamax with alpha-beta pruning, principal-variation search after the first move, transposition bounds, check extensions, and bounded quiescence search. Quiescence will search captures, promotions, and check evasions only, with a fixed ply ceiling. Mate scores will include ply distance. No external game-history repetition state will enter the root decision, preserving equivalence between `startpos moves ...` and equivalent FEN reconstruction.

Move ordering will combine the transposition move, promotion priority, capture scores, killers, history, and deterministic UCI tie-breaking. The transposition table will be scoped to one `go` invocation and bounded to 65,536 entries with depth/age replacement. Fixed-size killer and history tables will be cleared on each new reconstructed position and new game. This retains useful intra-search caching while enforcing repeated-state isolation.

Evaluation will be a deterministic tapered score combining material, piece-square activity, mobility, pawn structure, passed pawns, doubled/isolated pawns, bishop pair, rook-file activity, king safety, and endgame king activity. Incremental material, pawn, phase, king, and hash data will be maintained by push/pop; tactical mobility and attack terms will be computed from the current position. All scores will remain from the side-to-move perspective and use consistent mate bounds.

Time control will start at receipt of every `go` command, use a monotonic clock, and reserve a fixed safety boundary of `max(1 ms, 15% of movetime)` for output and scheduling overhead. Search stops before that boundary, retaining the last completed root result. At 1 ms it will use the prevalidated legal fallback unless a completed search is already available. Time checks will occur at root moves, node entry, move loops, and quiescence boundaries. The output path will emit exactly one flushed bestmove, with no dependence on optional info output.

The bounded implementation order is:

1. Implement canonical protocol parsing, FEN serialization, and position reconstruction.
2. Implement board state, attack detection, push/pop, hashing, and exact clock/castling/en-passant handling.
3. Implement legal generation and terminal classification, then validate legality and restoration relations.
4. Add scoped caching and deterministic ordering.
5. Add incremental evaluation and tapered scoring.
6. Add iterative search, quiescence, mate handling, and bounded extensions.
7. Add the deadline controller and immediate legal fallback.
8. Run the fixed ledger in its prescribed order, followed by syntax, standard-library, UCI smoke, and deadline checks.

The final artifact is accepted only when all mandatory ledger relations pass, every observed conservative deadline margin remains positive under the ledger’s `raw_margin - 1 ms` rule, and no strength-oriented improvement is retained if it threatens legality, state equivalence, protocol correctness, terminal handling, or deadline behavior.
